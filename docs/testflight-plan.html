Phase 1 · Enroll and set up

Oct 12 to 15

Your clicks, about an hour in total, plus Apple's enrollment check. Run commands in Git Bash, or type them after ! in a Claude Code session. Never paste the contents of the .p8 key file into a chat.

1Enroll in the Apple Developer ProgramYouApple20 min, then 1 to 2 days

Do this

  1. On your iPhone, install Apple Developer (by Apple) from the App Store.
  2. Open it › Account › sign in with your personal Apple Account › Enroll Now.
  3. Choose Individual. Enter your legal first and last name exactly as on your ID, your street address and phone.
  4. Take the photo of your driver's license or state ID when it asks. Pay 99 USD; it renews every year.
  5. Wait for the "Welcome to the Apple Developer Program" email.
  6. Open developer.apple.com/account › Membership details › copy the Team ID (10 characters, not a secret). You need it in step 7.

On a computer instead: developer.apple.com/programs/enroll. Apple's guide: enrolling in the app.

Where it can snag

  • Name doesn't match your ID. A nickname or short name delays the review. Use the name on your ID; as an individual it is shown on the App Store as the seller.
  • Switching devices midway. Apple requires the same iPhone for the whole in-app enrollment. Start and finish on one phone.
  • No confirmation after 24 hours. Contact Apple with your Enrollment ID: developer.apple.com/contact › Membership and Account. Don't enroll a second time.
  • Two-factor is off. Turn it on first: Settings › your name › Sign-In & Security. You also have to be 18 or older.
  • Which Apple Account. Use one you'll keep after graduating: the app and its yearly renewal live on it.
  • Renewal. The in-app enrollment renews by itself. If the membership lapses, the app leaves the App Store (copies already installed keep working).

Done when: you have your Team ID.

2Accept the agreementsYou5 min

Do this

  1. Open appstoreconnect.apple.com with the same Apple Account › Business.
  2. Accept the latest agreement it shows.
  3. Same page › Agreements tab › Compliance › Digital Services Act › Complete Compliance Requirements › This is not a trader account › Done.
  4. Open developer.apple.com/account: if a banner asks you to accept an agreement, accept it too.
  5. Optional: install the App Store Connect app on your iPhone to see build and review status on the go.

Where it can snag

  • Paid Apps, tax and banking forms. Leave them alone. A free app doesn't need them.
  • "New App" missing later, or a release run that says "agreement". An agreement is waiting. Apple updates them a few times a year, and cloud signing stops until you accept the new one.
  • Trader question. Apple says you decide this yourself. A free app, US only, with no income is the "not a trader" case.

Done when: Business shows no agreement waiting.

4Create the app recordYou3 min

Do this

  1. App Store Connect › Apps › (+) › New App.
  2. Platforms iOS; Name Straight Bussing; Primary Language English (U.S.); Bundle ID io.github.blobberus.straightbussing; SKU straightbussing-ios; User Access Full Access › Create.

Where it can snag

  • The bundle ID isn't in the list. Do step 3 (or run step 8 once), wait a minute, reload.
  • "The app name you entered is already being used". Names are unique across the App Store. Try a variant such as Straight Bussing Shuttles (30 characters at most) and tell Claude, so the listing matches.
  • No (+) button. An agreement is still waiting (step 2).
5Create the App Store Connect API key (Admin)You5 min

Do this

  1. App Store Connect › Users and Access › Integrations › App Store Connect API.
  2. First time only: Request Access and accept the terms (often approved at once).
  3. Team Keys tab › Generate API Key (or +) › Name GitHub Actions › Access Admin › Generate.
  4. Click Download API Key right away (AuthKey_XXXXXXXXXX.p8) and save it in your password manager.
  5. Copy the Key ID (in the key's row) and the Issuer ID (above the list).

Where it can snag

  • The .p8 downloads only once. If you lose it, Revoke the key, make a new one, and redo step 7.
  • The wrong role. It has to be Admin (Apple's cloud signing refuses the others), and a key's role can't be changed later. Wrong role: revoke and make another.
  • Team Keys, not Individual Keys.
  • Never paste the .p8 contents into a chat, an email, an issue or a commit.

5b · Second key for reading feedback (after Claude finishes Phase 0)

  1. Same page › Team Keys › (+) › Name Feedback reader › Access Developer › Generate › Download.
  2. Save the .p8 in a folder outside the project, then tell Claude its Key ID. Claude tells you exactly where the feedback tool looks for it.

Where it can snag

  • Don't save it inside Documents\straight-bussing: anything in that folder can end up in a commit.
6Create the appstore environment on GitHubYou2 min

Do this

  1. Repository settings › Environments › New environment › name appstore › Configure environment.
  2. Tick Required reviewers › add blobberus › Save protection rules.
  3. Deployment branches and tags › Selected branches and tags › Add deployment branch or tag rule: main (Ref type Branch), then v* (Ref type Tag).

Where it can snag

  • The name. Exactly appstore, lowercase.
  • Forgot the main rule. The run fails with "not allowed to deploy to appstore". Add the rule and start a new run.
  • Why this matters. Every upload with the Admin key waits for your click, so no script, agent or leaked token can use it without you. Claude can't create this one for you: it is a repository setting.
7Store the key in GitHub: 3 secrets and 1 variableYou3 min

Do this

Replace the CAPITALS with your values. In Git Bash (or after ! in Claude Code):

gh auth status
gh variable set APPLE_TEAM_ID -R blobberus/straight-bussing --body "TEAMID1234"
gh secret set ASC_KEY_ID -R blobberus/straight-bussing --env appstore --body "KEYID12345"
gh secret set ASC_ISSUER_ID -R blobberus/straight-bussing --env appstore --body "xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx"
base64 -w0 ~/Downloads/AuthKey_KEYID12345.p8 | gh secret set ASC_KEY_P8 -R blobberus/straight-bussing --env appstore
gh secret list -R blobberus/straight-bussing --env appstore

In PowerShell, the base64 line is instead:

[Convert]::ToBase64String([IO.File]::ReadAllBytes("$HOME\Downloads\AuthKey_KEYID12345.p8")) | gh secret set ASC_KEY_P8 -R blobberus/straight-bussing --env appstore

Where it can snag

  • Swapped IDs. The Key ID is 10 characters; the Issuer ID is long, with dashes.
  • Copying the key's text by hand. Don't open the file. The command encodes the whole file, including its BEGIN and END lines.
  • Variable vs secret. APPLE_TEAM_ID is a repository variable (no --env). The three ASC_ ones are environment secrets (--env appstore).
  • Wrong GitHub login. gh auth status must show blobberus.
  • Check. The last command lists the three names (never the values). Afterwards, delete the .p8 from Downloads; your password manager has it.
8Run the release (build 1)YouApple2 min, then 20 to 30 min

Do this

  1. Actions › iOS release › Run workflow › Branch main, Dry run unticked › Run workflow. (Or ask Claude to start it.)
  2. Open the run › Review deployments › tick appstore › Approve and deploy. github.com in your phone's browser works too.
  3. Wait for the green check, then Apple's email that the build is processed (minutes to an hour).

Where it can snag

  • The run sits at "Waiting". It needs your approval: the yellow box at the top of the run.
  • A red step in the first minutes. Its message says which of steps 3 to 7 is missing. Fix that, then start a new run.
  • "This build number was already uploaded". Start a new run instead of Re-run (the build number is the run number).
  • It registered the bundle IDs and stopped. Do step 4, then run again.
  • Green, but no email after 2 hours, or an email with "ITMS-" in it. Send the email text to Claude.
  • TestFlight says "Missing Compliance". It shouldn't (the app declares no special encryption). If it does: choose None of the algorithms mentioned above.
9Install it from TestFlightYou10 min

Do this

  1. App Store Connect › Apps › Straight Bussing › TestFlight › Internal Testing › (+) › group Me › add yourself › add the build.
  2. On your iPhone, install TestFlight from the App Store. Open the invite (email, or it appears in TestFlight) › Accept › Install.
  3. TestFlight › Straight Bussing › turn on Automatic Updates.
  4. Open the app › About: it shows 1.0.0 (build number).

Where it can snag

  • No invite. It goes to your Apple Account's email, and TestFlight must be signed in with that same Apple Account.
  • The build isn't listed. It is still processing, or it isn't in the group yet (Builds › the build › Groups › +).
  • No Lock Screen countdown. Settings › Apps › Straight Bussing (iOS 17: Settings › Straight Bussing) › Live Activities on; and Settings › Face ID & Passcode › Allow Access When Locked › Live Activities on.
  • The nearest stop is wrong. Settings › Privacy & Security › Location Services › Straight Bussing › Precise Location on.
  • No bus alerts. A Focus (Sleep, Do Not Disturb) can hide them; also check the app's Notifications in Settings.
  • Expiry. Each build stops working after 90 days. The next build replaces it.

Done when: the app opens on your iPhone and About shows the build number.

Phase 2 · Round 1: you alone

Oct 15 to 21

Use the app on your normal rides. Tick a test when it passes and type the build number next to it. A is once on day 1, B is every ride, C to F across the week. Report anything off with the bug loop.

A · First launch 10 min

B · Every ride 2 min

C · Hard situations

D · Look and accessibility

E · Every feature once

F · Battery

Where Round 1 can snag

  • No buses running (night, weekend, break). Turn on Settings › Simulated buses to test the screens, judge times only with live buses, and turn it off afterwards.
  • Reports without a build number. Always include it; About shows it.
  • Your screenshots show your location. Fine to send to Claude here; Claude never posts them.
  • Timing a bus. Count when it stops at your stop, not when you board.
  • After each new build, re-check the fixes its What to Test note lists, first.
  • Battery test. Do it once with Low Power Mode off; Low Power Mode changes how often the app refreshes.

The bug loop

How a problem you find turns into a fixed build on your phone.

  1. You reportScreenshot (side button + volume up) and one sentence to Claude, or TestFlight's Share Beta Feedback.
  2. Claude fixesFiles it with a severity, fixes iOS (and the website if it has the same bug), runs the tests.
  3. New buildClaude starts it, you tap Approve. About 30 minutes later TestFlight updates the app.
  4. You re-checkTry the fix on the new build; Claude closes the issue.

Report template

Build: (About shows 1.0.0 (N))
Where: (stop or screen)
When: (time)
Expected:
What happened:

Example: "Build 14, Ellis and 57th, 8:40 AM: said 3 min, the bus came at 8:49."

How fast each kind of bug gets fixed

LevelWhatFixed
P0Crash or freeze; old or wrong times shown as live; a missing stale warning; call buttons that don't call; anything that looks official; data leaving the phone beyond the privacy pagea new build the same day
P1Wrong route, stop or direction; Live Activity or bus alert wrong or missing; a dead end; the sheet stuck; a first screen slower than 2 secondsthe next build (every 2 to 3 days)
P2Layout, wording, contrast, small visual glitchesin a batch
P3Ideas and wishesthe after-launch list

If you get stuck

  • Copy the exact error text (or a screenshot) to Claude. Crop out your location if the screenshot is going anywhere public.
  • A failed GitHub run: open it, click the red step; the first red line usually says what to do. Or tell Claude the run link.
  • Account, enrollment or payment problems: Apple Developer Support.
  • Never share the .p8 file's contents, your Apple password or a two-factor code, with anyone, Claude included.
  • Long version of every step: docs/APPSTORE-SUBMIT.md and docs/TESTFLIGHT-PLAN.md.
