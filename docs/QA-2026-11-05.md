# QA and optimization run, 2026-11-05 (the glass interface on the live site)

Owner request (2026-11-05): "Transfer the interface of the experimental build to the current main build of straight
bussing. Check for bugs and data collection for logins that may be messed up during the change. Run an optimization
run and bug test."

The transfer itself is recorded in docs/ARCHITECTURE.md "Glass interface on the live site" (main 34d86cf7, sw
sb-v2-98). This file is the independent bug test and optimization run on that build: what was checked, what was found,
what was fixed, the before / after numbers, and what only a real iPhone can confirm. Three engineers worked in
parallel (lead: performance, the service worker, usage statistics, the status banner; one on narrow screens, large
text and accessibility; one on every flow and failure). Every fix is its own commit with a test; the browser suite
went from 830 to 865 tests, all passing, and `tools/test_precache.py` passed before every push.

Ship checklist order is used for severity: P0 rider safety, P1 near-safety / times, P2 speed or a broken flow, P3
polish.

## 2. Optimizations (lead)

| Commit | What | Measured (headless Edge, SwiftShader, 393 x 852 at DPR 2) |
|---|---|---|
| `d5cbb069` | Bus glide frames batched: badges move only once some badge has moved 1 px since the last drawn frame, then all together (Leaflet draws whole px anyway). Every redraw repaints the blurred glass. | Demo, 9 buses, idle 5 s: drawn frames 127 -> 100, GPU time -23% (2 runs). |
| `411480fb` | Map names: the basemap's text layers are read once per style change. `textAt()` called MapLibre's `getStyle()` (a deep copy of the whole style) for every box the label pass tried, after every move and every basemap idle. | 4 pans + 4 zooms at 4x CPU: `textAt` 216 / 192 -> 70 / 73 ms. |
| `2c4a0174` | Map names: a pan that places the same names keeps their markers (the signature is in layer px, not screen px). | Label pass 274 / 217 -> 106 / 118 ms; all JavaScript in the run 2232 / 1992 -> 1228 / 973 ms (with the commit above). |
| `128e6f56` | (smoothness, see 1) frames at half a pixel: part of the batching saving given back so no badge ever jumps 2 px. | Demo idle 5 s, a quiet moment (3 runs): 1 px step 8 drawn frames, half pixel 12, the transferred build 40 (GPU 54 / 76 / 244 ms). |
| `82974bc1` | Bus glide sleeps until a badge can next need drawing (`nextWakeMs`: the fastest badge's next pixel, 4 m along its line for the notch, or the end of a move) instead of running on every display frame all day. | Demo mode, 9 simulated buses, idle 5 s, 3 interleaved runs (correction: the commit message says "live-like idle 5 s with 12+ buses"; it was measured in demo mode with 9 buses): main-thread frames 766-795 -> 34-44, main-thread time about 148 -> 19 ms, style recalculation -83%, paint -88%. |

Against spec 12.2's budgets (set against the first redesign: drag GPU 4.67 ms + 10%, idle GPU 5.47 ms + 15% per frame),
the GPU per-frame numbers still miss in this CPU-rendered setup: that cost is the blur itself, which the design keeps.
What this run cut is how often the glass is redrawn (idle GPU time -29%) and the main-thread work around it.

### Other measurements

- **Memory**, 10 minutes of the live site with real polling (12 to 14 buses), a tab / route page / back every minute:
  JS heap after GC 10.5 -> 11.5 MB, DOM nodes 864 -> 885 (they follow the bus count), listeners flat. No leak.
- **First contentful paint**, 4x CPU, third parties blocked, cold, median of 6: the pre-transfer build (sb-v2-89) 590
  ms, the glass build 530 ms (budget < 700 ms).
- **Blurred surfaces at rest**: demo 6 on 17.4% of the screen, live 6 on 16.3% (budget 6 / 22%). At 320 x 640 the same
  six cover 22.1% (the controls keep their size on a smaller screen).
- **Steady state** (live, 25 s at 4x CPU, after `82974bc1`): the glide loop 162 ms (was 755 ms), the app idle 93% of
  the time; schedule, operating and route-list work a few ms per poll.
- **Slow network, cold first visit** (Fast-3G-like 1.6 Mbps / 150 ms, 4x CPU, nothing cached): the app's own code
  cannot run before `maplibre-gl.js` (about 800 KB from unpkg) has downloaded and run, because it is a classic script
  ahead of the module; the live feed request starts only after that (about 6.5 s here; the local server sends the
  app's files uncompressed, so this overstates it). Repeat visits and the installed app are cached. Not changed in
  this run (it means restructuring the boot: map libraries loaded without blocking, the map created when they arrive);
  see owner decisions.

## 3. Verified, no change needed

- **Service-worker update sb-v2-89 -> current** (an installed home-screen client, simulated in headless Edge: the old
  build served and installed, the files swapped, the app brought to the foreground): the new worker took control in
  1 s, the page stayed on its old code while visible, reloaded once hidden, and then had only the new cache (130
  entries, every one byte-identical to the server); an offline reload showed the new interface and the feed banner.
  With a trip in progress the reload waited until the trip ended. Re-run after `72ca82ca`: the same. Every shell file
  precached (`test_precache.py` 6/6 before every push).
- **Anonymous usage statistics** after the reworked Settings sheet (the real app, the receiver stubbed by request
  interception, nothing reached the owner's Sheet): first visit = one start row with every field (`v e id sid day dow
  time app ver nu`, app "browser", ver "2.0.0", nu 1); a reload continues the visit (no second start row); going to the
  background sends an end row with the length rounded to 5 s; "Include my nearest stop" sends one place row with the stop
  name (no coordinates); with "Share how long I use the app" off no end row; demo mode sends nothing. The two Settings
  switches save `{dur, zone}` as before. Same rows as before the transfer.
- **Wording, web banner vs iPhone status pill** (Kit `LiveText.pill`): the full sentences are identical; the web's
  compact one-line forms keep the same meaning ("Live data lost. Times may be off.", "No live data. Don't rely on
  times.", "Last update 1:23 PM. Times approximate.", "Live data delayed. Times may be off.", "No shuttles reporting
  locations"). Differences by design: the web also flags "never polled" after 20 s (the app shows nothing until its
  first poll), and only the web has the compact banner's Details, the 2.5 s hold and the 0.8 s chip guard (the app
  keeps its 1 s context-bar guard after Retry).
- **Retry**: tapped again and again during a trip, also while the feed comes back, it never moves and the trip never
  ends (e2e); stale and failed feeds are always flagged.
- Narrow and large-text layouts, keyboard up, focus order, focus traps, contrast on glass, reduced motion / reduced
  transparency / Increase Contrast fallbacks, phone landscape, the desktop frame (layout engineer; open items below).
- Flows (flows engineer, light and dark): a live trip through an outage (flagged), denied location, theme switch,
  stop sharing, the back / browser back / Escape matrix, Lines by Time (none, settle, set again), Alerts, About, the demo
  chip, map-order drag, a closed route, picking a station, bus alert settings, Show running during an outage, route
  search during an outage and with no results, the tab bar minimize, landscape, freeze / resume, rapid taps. A first
  live poll that fails or hangs ends after 8 s and the views say live times are unavailable with 773.702.8181 (no

## 5. Needs a real iPhone (or a mid-range Android)

- The GPU budgets of spec 12.2 (headless WebGL and compositing run on the CPU here, so blur costs far more than on a
  phone): ten sheet drags with buses moving, a 10 s pan, tab switches; any visible stutter fails.
- glass-lite: it switches on when more than 20% of frames take over 24 ms in the first 10 s of use. iPhone Low Power
  Mode caps Safari at 30 frames a second (33 ms), so glass will turn solid in Low Power Mode (probably welcome; confirm).
- The installed app updating from sb-v2-89 on the home screen, and the lie-fi fallback on a real captive portal.
- The keyboard in Safari (fields and results above it), Dynamic Type through `-apple-system-body`, safe areas,
  VoiceOver order, Reduce Transparency (iPhone Safari cannot report it), the feel of the 0.8 s chip guard.

## 7. Harness notes (for the next run)

- Edge installs the user's extensions into a fresh headless profile about 10 s after launch, and one of them opens its
  own tab, which hides the page under test (rAF stops, visibilitychange fires). Launch with `--disable-extensions
  --disable-component-extensions-with-background-pages --disable-sync --no-service-autorun --disable-default-apps`.
  This likely explains earlier "outlier runs" and hung CDP events in the redesign notes.
- With the service worker active, CDP Fetch interception on the page misses the worker's requests: use
  `Network.setBypassServiceWorker`.
- Serve snapshots (`git archive <commit> web`) for A/B runs, never a working tree that changes during the run.
- The trace categories `devtools.timeline,viz,gpu,cc,toplevel` in `recordContinuously` mode are enough for the frame,
  GPU and style numbers; the heavier set made input events stall for minutes.
