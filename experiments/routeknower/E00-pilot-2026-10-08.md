# E00: Pilot backtest on the first real day

Date: 2026-10-08 · Agent: Claude (lead session) · Data: `origin/data:data/ground_truth/arrivals.csv` snapshot at 15:12 CDT,
1854 rows, 2026-10-08 04:59 to ~15:00 CDT, sha256 `e1cd6864cb277b6cd84e854a0d59ea06efe8829d3568a7dd7c7e038c8e128b24`
Question: does the existing pipeline (`tools/backtest.py`, `tools/model_*.py`) run on real data, and what do the first numbers look like?
Method(s): M0 schedule, M1 Passio, global median, segment x hour median, M3 shrunk hierarchy, M4 shrunk + EWMA (see RouteKnower.md §5)
Protocol: `tools/backtest.py` 70/30 time split on rows (not days), rolling origin skipped (`--no-rolling`): too little data.
Leakage checklist: time-ordered yes; same information time as Passio yes; split by days NO (only one day exists).

## Decision
**Inconclusive.** One service day; the model trained on the morning and was tested on the afternoon, so daypart
buckets for the test hours barely exist (most test predictions fell back to route x daypart). There is 1 test day,
so §6.5 significance is impossible. What it does show: the pipeline works end to end on real data, and the
shrunk hierarchy already beats the schedule at the 2-5 min lead on these rows. Passio's 5-10 min MAE (1,973 s, n = 10)
is almost surely a data-matching bug, not Passio: see RouteKnower.md §3.3 and E01.

## Follow-ups

## (B) Arrival time at Passio's lead (same information time for every method)

Query time q = actual arrival - Passio lead. Ours = last arrival the bus had logged by q + predicted
segments (clamped to >= q). Interval: Fenton-Wilkinson sum of log-normals with correlation rho = phi,
width calibrated on the training period. Passio is only scored on these same rows.

## Live-bus Kalman filter (simulation, `python tools/model_kalman.py`)

Position error: filtered 10.1 m vs raw GPS 19.7 m. ETA MAE: constant-velocity extrapolation 223 s, filtered position + learned speed 12.0 s, raw GPS + learned speed 11.5 s. Lesson: the filter cleans position and rejects GPS jumps; the ETA must come from learned segment speeds, not from the instantaneous velocity.

## How to read this

- (A) isolates the travel-time model; (B) is what a rider feels and is the fair comparison with Passio.
- Coverage should be near 80%; pinball loss rewards sharp AND calibrated quantiles (lower is better).
- Schedule rows are only those whose stop pair exists in `web/data/route_stops.json`.
- Reproduce: `python tools/backtest.py`.
